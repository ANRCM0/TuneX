# Deviations from the decompiled RelayX original

Each entry is something this replica does differently from the analysis tree (`/workspace/111/relayx-analysis`). "Verified" means a teammate or the Lead checked it against the source or a test run. It does not mean byte-identical to a live upstream deployment.

## Kernel and HTTP stack

1. **Sentry middleware is hand-written.** `hono/sentry` is not an export of hono 4.13.13. `apps/backend/src/middlewares/sentry.ts` keeps the `{dsn, environment, enabled, beforeSend}` shape. When disabled or not production it calls `next()`. `beforeSend` still drops `HTTPException` with status < 500. Blast radius: no real Sentry transport unless you wire one; request flow matches the guard.

2. **OpenAPI helper rename.** `hono-openapi@1.3.5` calls the old `h2` factory `openAPIRouteHandler`, and its built-in validator is Standard Schema, not zod. `apps/backend/src/openapi.ts` re-exports `openAPIRouteHandler as h2` and routes keep `@hono/zod-validator`'s `zValidator`. `describeRoute` 200 schemas go through `resolver(...)`. Blast radius: generated OpenAPI can differ in validator metadata; HTTP validation is still zod.

3. **License client uses `fetch`, not `hc()`.** `apps/backend/src/services/license.ts` `call(method, path, {query, body})` hits `LICENSE_URL` with the same paths and maps failures to `HTTPException(status, {message: error.error})`. Reason: avoid a cross-app typed client. Blast radius: no compile-time coupling to license-server types; a body-shape drift would be runtime-only.

4. **Zod models are scalar-only and hand-generated.** `apps/backend/scripts/generate-zod.mjs` writes `apps/backend/src/generated/zod/index.ts` (23 model schemas + `jsonSchema = z.any()`). Relations and Prisma input types are omitted. `prisma-zod-generator@3.3.1` emitted only operation schemas (`NodeGroupFindUniqueZodSchema`, …). `@1.32.2` reported success and wrote nothing. Regenerate with `pnpm --filter @relayx/backend zod:generate`. Blast radius: route code that only reads scalars is fine; anything expecting relation schemas will not compile.

5. **Fernet boot key.** Upstream's placeholder `CONFIG_SECRET` is not 32 url-safe base64 bytes, so `services/fernet.ts` threw at import and the process never listened. Default is now `5HVa-B4kYWf9qI524XABW2lg0g5OZZfyq9BoZWNrHp0=` (sha256 of `relayx-replica-fernet-key-v1`, urlsafe-base64), also in `.env`. Generate your own before any real deployment. Blast radius: tokens are not decryptable with the upstream key unless you set `CONFIG_SECRET` to that key.

6. **StackAuth side-effect import.** `middlewares/auth.ts` imports `../services/stackauth` so `TOKENS.StackAuth` is registered. Nothing else value-imported it, and cookie auth plus `userService.changePassword` threw `[container] nothing registered for token "StackAuthService"`.

## Queues, bot, stats

7. **BullMQ only when `REDIS_URL` is set.** `bullmq/queue.ts` builds `Redis(REDIS_URL, {maxRetriesPerRequest: null})` only then. Otherwise `queueDefault` is null and `initBullMQ()` logs and returns. The server boots with no Redis. There is **no BullMQ Worker** in the analysed original either: queue + scheduler only. `bullmq/jobs.ts` registers 12 cron names whose handlers do not run in-process. Verified by ops-dev: boot log `BullMQ cron scheduler initialisation skipped: REDIS_URL is not set`.

8. **`/queuedash` is a small read-only router.** Module 056's `The(...)` factory is not a frozen dependency. `bullmq/queuedash.ts` returns `{queues:[{displayName,name,type,connected,schedulers}]}` from `getJobSchedulers()`. Without Redis, `connected: false` and `schedulers: []`. Curl on `:3000` returned 200.

9. **Telegram transport is `fetch`, not Telegraf.** `services/telegram.ts` calls `https://api.telegram.org/bot<token>/<method>` and long-polls `getUpdates`. Commands, callbacks, keyboards, and Chinese strings follow the decompile. `start()` logs and returns when `TELEGRAM_BOT_TOKEN` is unset (observed at boot).

10. **Stats SQL is SQLite-shaped.** Aggregates live in `services/stats.ts` (`TOKENS.Stats`). Date bounds are computed in JS, shifted to Asia/Shanghai, and bound as parameters instead of MySQL `NOW() - INTERVAL n DAY`. Grouping uses frozen `getDateGroupBy` / `toLocalTZ`. `/traffic` still merges today's Redis tunnel counters. `/admin/stats` reuses frozen `AdminStatsQuerySchema` (`z.coerce.date`, `aggregate_by` default `"day"`); upstream used inline `z.string()` for the dates. Omitted params behave the same. Curl of `/admin/stats`, `?aggregate_by=month`, and `/admin/stats/traffic` returned 200.

11. **`cronSaveTraffic` counts keys.** It returns `Object.keys(traffics).length`. Upstream `traffics.length` is `undefined` on a plain object and is a TypeScript error.

## DNS

12. **Cloudflare and Huawei are in-file HTTP clients.** `cloudflare` v5 and `@huaweicloud/huaweicloud-sdk-dns` are not installed. `services/dns/cloudflare.ts` and `services/dns/huawei.ts` speak the same endpoints; Huawei signs `SDK-HMAC-SHA256`. **Not verified against live accounts.** `relayx/tests/unit/dns.test.ts` was 32/32 against mocks.

13. **No CNAME, and DNS config is plaintext JSON.** The original only has A/AAAA. `DNSProvider.config` is a Json column, not Fernet. Encrypting it would break API round-trips.

14. **DNS method union mismatch is typing-only.** `services/node.ts` says `"add" | "delete"`; `services/in_node_group_dns.ts` says `"create" | "delete"`. Only `"delete"` is passed (module 026), through a cast. No runtime effect.

## Container tokens

15. **Extra literal tokens.** Frozen `TOKENS` has no Notify or DNS entries. `services/notify.ts` registers `"NotifyService"`. DNS uses `"DNSProviderService"`, `"InNodeGroupDNSService"`, `"DNSProviderFactory"`. `register` is last-wins and module-level registration is idempotent.

## License server and agent

16. **License server listens on 3100**, matching root `.env` `LICENSE_URL` (the Python reference used 8899). Fernet uses `setAutoPadding(false)` plus manual PKCS#7 so tokens match Python `cryptography.Fernet` byte for byte. Without that, Node's default padding made each token 16 bytes longer. `apps/license-server` tests: 6 files / 44 passed, including the 18 wire assertions from `verify_license_server.py`. `docker build` was not run (no daemon).

17. **The agent is a from-scratch Go program**, not the upstream binary. See [AGENT.md](AGENT.md). TCP/UDP forward, Shadowsocks TCP and UDP (three AEAD methods, plus method `none` when `ssu` has no cipher — the UDP out-node hop), SOCKS5 (CONNECT and UDP ASSOCIATE; SOCKS BIND rejected), gost relay CONNECT (the out-node hop), gost relay BIND (remote TCP over smux v1 and remote UDP as SOCKS frames on `rudp`), the `relayx` websocket listener (HKDF bearer token, smux v1, uTLS HelloChrome_Auto over a self-signed cert), QUIC (v1/v2, ALPN `h3`/`quic/v1`, self-signed cert, dialer skips verification), TLS and mTLS (smux v1 over TLS for `mtls`), WSS and MWSS (websocket on `/ws` over that TLS; smux v1 for `mwss`), MTCP (smux v1 over plain TCP), and WireGuard-via-`wg` are real. VLESS over REALITY is real (Chrome uTLS session-id seal; `xtls-rprx-vision` padding is stripped, without splice; the server disables its own session tickets so the library can mimic dest's ticket). mieru is real (`enfein/mieru` v3.36.0, TCP CONNECT; the library binds all interfaces). VMess returns `not implemented in replica`. OpenVPN TCP is accepted far enough to decrypt `P_DATA_V2`, but there is no TUN. A REALITY listener whose handler is not `vless` is still a stub. A `wss`/`mwss` service whose handler is not `relay` is still treated as plain TCP. A TCP forward with `handler.metadata.proxyProtocol` set to `1` now requires and strips a HAProxy PROXY v1 header. Plain TCP/UDP forwards, VLESS, mieru, Shadowsocks TCP and UDP, SOCKS5 CONNECT and UDP, gost relay CONNECT, remote TCP and WireGuard post gost HTTP observer stats. WireGuard reads cumulative `wg show transfer` counters and reports the delta. OpenVPN's service name `ovpn-<id>` is also skipped by the panel's prefix strip, matching upstream. The post uses the plugin URL as written (the panel does not put `node_id` on it), so Redis per-node stats stay empty while tunnel traffic still increments. The `relayx` dialer reuses one smux session for the same address, key, host and path. A UDP-tunnel entrance is still `handler=ssu` with `bind` and no cipher; stock gost rejects that handler without auth, and this replica treats a cipher-less `ssu` as shadowsocks method `none` rather than as UDP BIND. UDP BIND is the `rudp` service, which dials the relay handler. `pnpm agent:build` and `go vet ./...` passed. A live register against `:3000` now decrypts the license (`License loaded successfully`) and applies the Fernet `config` push. The license server's default `content` mode is `fernet` with upstream key2, not the panel `CONFIG_SECRET`. Renewals keep the old `content`, so an existing plaintext row has to be revoked and reissued. `plain` and `base64` modes remain for the Python reference.

18. **OpenVPN PKI is OpenSSL, not node-forge.** `apps/backend/src/utils/openvpn.ts` issues the same names and key usages (`RelayX OpenVPN CA` / `Server` / `Client`, serverAuth, clientAuth, RSA-2048 PKCS#1) with the `openssl` CLI because `node-forge` is not installed. `generateTlsCryptKey` is 16 lines of 32 hex digits (256 bytes) between the OpenVPN static-key markers, matching module 043. `tests/unit/openvpn.test.ts` checks the key length and that `openssl verify -CAfile` accepts both leaf certs. The agent can wrap and unwrap an OpenVPN 2.4 tls-crypt control packet, frame it on TCP, answer `P_CONTROL_HARD_RESET_CLIENT_V2` with `P_CONTROL_HARD_RESET_SERVER_V2`, carry a TLS handshake in the following `P_CONTROL_V1` payloads, and seal `P_DATA_V2` with AES-GCM (tag before ciphertext, implicit IV from the HMAC key). Key method 2 derives those keys with the OpenVPN TLS1.0 PRF (`OpenVPN master secret` / `OpenVPN key expansion`) so the client's send key is the server's receive key. A test runs that exchange as TLS application data on the control channel, then writes a `P_DATA_V2` packet on the same TCP connection. The control stream demuxes it and the server decrypts it (`internal/openvpn`). The manager now listens for `listener=openvpn` (handler `tungo`): it finishes that handshake, answers `PUSH_REQUEST` with `PUSH_REPLY` (peer-id plus ifconfig from the `server` CIDR), and counts decrypted payloads. An inner IPv4 UDP datagram is forwarded with `net.DialUDP`. An ICMP echo request for the tunnel gateway is answered locally; other ICMP is dropped. An inner IPv4 TCP SYN is dialed and later payloads are written to that socket. A background read seals whatever the peer sends next, so the reply does not have to arrive before `Handle` returns. Other IP protocols are ignored. The official OpenVPN 2.6.19 client completes tls-crypt, the TLS handshake and key method 2, then accepts `PUSH_REPLY` including `cipher AES-256-GCM`. This container has no `CAP_NET_ADMIN`, so the client stops at `TUNSETIFF` and no TUN traffic is carried. OpenVPN UDP uses the same handshake with one datagram per packet. A received control message is acknowledged with a standalone `P_ACK_V1`; an ack that has not been flushed yet is still piggybacked on the next write.

19. **Deployment-layer `/api` strip is emulated in the server entry.** The analysed app mounts all routers at the root, its auth whitelist entries have no `/api`, yet the URLs it hands out for its own API carry the prefix: node observer `POST ${SITE_URL}/api/tunnel/observer` (`052:1231`), payment callback `${SITE_URL}/api/pay/:id/callback`, and OpenAPI `servers: [{url: "/api"}]`. The analysis concludes the prefix is stripped outside the package (`work/verify_live/01_api_prefix.sh`, `reports/BUSINESS_LOGIC_DEEP.md` U1). A live node posting to the replica therefore got `401` from the auth guard, because `/api/tunnel/observer` is not whitelisted. `apps/backend/src/index.ts` now rewrites one leading `/api` before `app.fetch`, forwarding node-server's `env` so `getConnInfo` still sees the peer address. Effect: `POST /api/tunnel/observer` reaches the same unauthenticated handler as `/tunnel/observer` and returns `{"ok":true}`; `/api/system/config/site` returns 200; `GET /plan` still works. Routers and guards in `app.ts` are unchanged, so `docs/PARITY.md` still holds. Verified live with `curl` and the agent's 5-second observer loop (backend access log shows `POST /tunnel/observer` 200 and the agent stops warning). Blast radius: a request to a real path whose first segment is the literal `api` would be rewritten; no such route exists here.

20. **`zod-openapi` is a runtime dependency of the OpenAPI endpoint.** `hono-openapi@1.3.5` delegates schema conversion to `@standard-community/standard-openapi`, whose zod adapter imports `createSchema` from `zod-openapi` v4. Without it, `GET /openapi.json` (and `/docs`) returned **500** — the routes were documented but the document could not be generated. `zod-openapi@^4.2.4` is now a direct dependency; the endpoint returns 200 with 116 paths and `scripts/e2e-local.sh` asserts it. Blast radius: one extra production dependency; the generated document is what the replica's own `describeRoute` calls declare.

## What is NOT a deviation

- `/license` is mounted twice on the public router in `apps/backend/src/app.ts`. Upstream `112__src__app.ts` does the same.
- `SystemConfigService.getAllConfigs` does not backfill defaults. `getConfigs` does. Same split as the original.
- `/docs` and `/openapi.json` sit behind `businessLicenseRequired`.
- `/queuedash` and `/health` are mounted before `authRequired`. `sentry` + `authRequired` apply to the routes registered after them.
- There is no BullMQ Worker in the original. Jobs are scheduled, not executed in-process.
